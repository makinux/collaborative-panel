# collaborative-panel

複数のモデルが異なる発想レンズの下で独立にアイディアを出し、互いの案を交配(建て増し/合成/救済/空白埋め)し、ファシリテータが順位付き・検証可能なショートリストへ統合する——[adversarial-panel](https://github.com/makinux/adversarial-panel) の姉妹版となる、**多モデル協調ブレインストーミング**の Claude Code スキルです。

## なぜ作ったか

敵対的レビューは間違いを殺しますが、殺したあとの空席には何も置きません。「作るより見抜く方が簡単」という検証非対称性には易しい側があり、そこから新しい選択肢は一つも出てこない。生成の仕事は相変わらず残ります。

素朴な解決は静かに失敗します。開いた問いを同じ形で二つのモデルに投げると、返ってくるのは重なり合った「誰でも思いつく最初の5案」。モデルファミリーを替えてもほとんど効きません——異質性が非相関にするのは**誤り**であって、**発想**ではないからです。批判の的は相手の主張という外部にありますが、発想の的は自分の内側にあり、そこは重みが違っても似た形に凹んでいます。

だから「複数モデルに聞く」こと自体には価値がありません。効かせるのは次の3つの設計特性です:

- **非相関な発散(Decorrelated divergence)** — blindなRound 1+パネリストごとに異なる**発想レンズ**。アンカリングは敵対版でいう盲点の共有に相当し、他人の案を見たパネリストは新領域ではなく変奏を作ります。
- **交配余剰(Combination surplus)** — どちらも単独では出さない案は、一方のRound 1と他方のRound 1の掛け合わせから生まれます。放置するとモデルは賞賛と言い換えを返すため、Round 2は建て増しと合成を件数で強制します。
- **潰さない収束(Convergence without mush)** — 40案の生データは成果物ではなく、テーマに丸めると案は死にます。原子性・帰属・検証可能性を保ったまま選別・具体化し、変な案は順位を付けない別枠で保存します。

## アーキテクチャ

![構成図:ファシリテータが互いに異なるレンズ付きのbriefを配布し、パネリストが相互交配して案と建て増しを返す](assets/architecture-ja.png)

骨組みは敵対版と同じで、配るものと返させるものが違います。ファシリテータ(メインセッション)は自己完結したbriefに**互いに異なる発想レンズ**——類推転移/逆転/ステークホルダー回転/資産再組合せ/制約シフト/スケールシフト——を1〜2枚ずつ載せて配布します。発想の脱相関を担うのはモデルの重みではなくレンズです。

パネリストの調達順は敵対版と同一で、**異質性を最大化する順**に選びます:

1. 別モデルファミリー(Codex等の外部CLIをBash経由で)
2. 別のClaudeモデル(Agentツールの `model` パラメータ)
3. 同一モデル+強制的なレンズ分岐

敵対版と違い、ファシリテータ自身も案を出せます(裁定者ではないため利益相反がありません)。ただし必ずラベルを付け、パネリストのレーンを侵さないこと。

デフォルトは**2パネリスト×2ラウンド**——発散には譲歩と防御のラウンドが要らないため、敵対版より1つ少ない構成です。

## プロトコル

![進行図:Round 0 フレーミング → Round 1 独立発散(検証ゲート)→ Round 1.5 下読み → Round 2 交配 → 統合](assets/protocol-ja.png)

白=ファシリテータの担当、紫=パネリストの担当。

| ラウンド | 内容 |
|---|---|
| **Round 0** | 自己完結したbriefを書く: 種・目的・評価軸・4行のアイディア書式・**数量ノルマ**(1体12案以上+ワイルドカード/スリーパーの自己指名)・**棄却済み主張リスト**(前段レビューで殺した主張のそのままの復活を禁止。前提を新しいメカニズムで攻めるのは許可)。期待する答えのカテゴリ一覧は書かない(シード漏れ) |
| **Round 1** | 全パネリストをblind・並列で起動。返り値は検証ゲートへ: 書式・ノルマ・**割当レンズを実際に使ったか** |
| **Round 1.5** | ファシリテータの数分の下読み: 近接重複の目星、事実誤認への中立な注記(放置すると上に建つ交配案が汚染される)、相互に必ず触れさせる案の指定 |
| **Round 2** | 案の山を交換し、貢献を種類と件数で強制: **BUILD≥5**(名指しできる何かを足す)/**COMBINE≥2**(両親明記の第3案)/**RESCUE≥1**(唯一許された批判形式——最弱の案の成立する版を見つける)/**WHITE SPACE≥2**/**SELECT** top 5+最安の次の検証 |
| **Round 3**(任意) | ショートリストの一枚企画書——賭け金が大きいときだけ |
| **Synthesis** | マージ表で重複を潰し(両方の発案者をクレジット)、Round 0の軸で順位付けし、4部で出力: 採用候補/ワイルドカード(順位なし)/空白領域/次の一手。**交配余剰**——どちらのRound 1にも遡れない案——を名指しする。ゼロなら「ゼロ」と書く(パネルが平行独白として走った証拠) |

確度%は付けません——未検証の案への数値確信度は較正の演技です。代わりに全案へ**最安の検証手順**を付けます。値付けするのは確からしさではなく、確かめる値段です。

## 全工程で守る3つの不変条件

| 不変条件 | 内容 |
|---|---|
| **Independence** | Round 1 の発散はblindで行う。他者の案を見たパネリストは変奏しか出さない |
| **Additivity** | Round 2 の貢献はメカニズム・規模・組合せ・適用先のいずれかを足していること。同意は歓迎、**空の同意**は賞賛の水増しで貢献0件 |
| **Hypothesis labeling** | ブレスト出力は設計上未検証。全案に最安の検証を付け、検証済みの顔をさせない |

## インストール

```
~/.claude/skills/collaborative-panel/SKILL.md
```

に [SKILL.md](SKILL.md) を置くだけです(Windowsは `%USERPROFILE%\.claude\skills\collaborative-panel\SKILL.md`)。

```powershell
# Windows (PowerShell)
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills\collaborative-panel"
Invoke-WebRequest https://raw.githubusercontent.com/makinux/collaborative-panel/main/SKILL.md -OutFile "$env:USERPROFILE\.claude\skills\collaborative-panel\SKILL.md"
```

```bash
# macOS / Linux
mkdir -p ~/.claude/skills/collaborative-panel
curl -o ~/.claude/skills/collaborative-panel/SKILL.md https://raw.githubusercontent.com/makinux/collaborative-panel/main/SKILL.md
```

## 使い方

明示呼び出しのほか、次のような自然文でも発火します:

> 「このアイディアを膨らませて」「加算事項を出して」「協調的パネルで」
> 「ブレストして」 / "brainstorm with multiple models" / "what else could we add"

向いているのは**答えではなく選択肢が足りない**局面——既存提案への加算、行き詰まった設計の代替案、レビューで穴の空いた章の埋め直し。主張の当否を決めたい問いには開かないでください。仮説しか返しません——当否は敵対版の仕事です。

2つのスキルは連結して使えます: **発散→硬化**(ショートリストを敵対パネルへ)、または逆順(殺してから埋め直す)。どちら向きでも接続端子は棄却済み主張リストで、これが無いと後段のブレストは前段で殺したばかりの主張を丁寧に再発明します。

## adversarial-panel との対応

| | adversarial-panel | collaborative-panel |
|---|---|---|
| 目的 | 主張の生存 | 発想空間の被覆 |
| Round 1 | 独立回答 | 独立発散+レンズ割当 |
| Round 2 | 相互批判 | 交配(BUILD/COMBINE/RESCUE/WS) |
| 禁止事項 | 論拠なき同意 | 中身のない賞賛 |
| 批判の扱い | 本体 | RESCUEの形だけ許可 |
| 失敗均衡 | 追従的収束 | 平行独白(交配余剰ゼロ) |
| 統合の原則 | 平均しない | 混ぜない |
| 出力の値付け | 確信度+反証条件 | 最安の検証手順 |
| **全員一致の意味** | (異種パネルなら)強い証拠 | **冗長——被覆の失敗** |

最後の行が最深の違いです: 同じ「全員一致」が、敵対版では証拠として、協調版では失敗の兆候として読まれます。

## 設計で塞いだ失敗モード

- **アンカー漏れ** — Round 1 完了前に他者の案を見る。blindが壊れた時点で以降は変奏の生産になる
- **当たり前の最初の5案** — ノルマもレンズも無いと両者が同じ5案を返す。ここでの一致は検証ではなく冗長
- **賞賛の水増し** — 言い換えと称賛の「建て増し」→ 足したものを言えない貢献は0件と数える
- **実現可能性の演技** — ブレスト出力を検証済みのように出す → 全案に最安の検証を付ける
- **収束のマッシュ** — 「シナジーを活かす」型のテーマに丸める。原子でなくなった案は実行できない
- **シード漏れ** — briefに期待カテゴリを書き、そのこだまが網羅に見える
- **棄却済み主張の復活** — 前段で殺した主張の同形再提案
- **新規性崇拝** — 驚きだけの順位付け。文脈適合を無視した案は別の提案であって良い案ではない
